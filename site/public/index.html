Find where the failure started.

Spoor is an open-source MCP server for VictoriaMetrics, Prometheus, Loki, Tempo and New Relic. Your AI agent asks what changed. Spoor answers in a few hundred tokens, with the cause on top and the echoes labelled.

Install Spoor View on GitHub

Version 0.3.0. Apache-2.0. Read-only, no LLM inside, same input gives the same answer.

Every caller of a broken service lights up. Spoor tells them apart.

With only raw query tools, an agent has to decide what to query, work out what normal looks like, page through results and guess which red service is the cause. It burns tool calls and often blames the loudest symptom, or an error that was always there.

Spoor does that work in plain, deterministic Go and hands the agent a short ranked answer it can check.

Across all three signals

Request rate, error rate, latency, CPU, memory and consumer lag; new and spiking error logs; slower and failing spans. All for the same window, against the same baseline.

Cause, not echo

Trace trees show where failures start and where latency is added. Callers that only suffer are labelled "originates in payment" and moved down.

Honest about gaps

Errors that were already there are listed as steady, not new. If a backend had no data, the answer says so. "No change" never stands in for "no data".

Measured, not promised.

Claude Code, run headless on six incidents (five faults and one where nothing is wrong), five times each. Once with the official VictoriaMetrics MCP servers alone, once with Spoor added. Claude Haiku, 60 isolated sessions.

Synthetic incidents and one small model, so treat it as a first data point. On real production logs, a 466-token answer stood in for about 296,000 tokens of raw evidence. Method, per-scenario results and caveats are in the benchmark write-up.

Set it up in three steps.

  1. Install

    One static binary for macOS, Linux and Windows. No runtime to install.

    OS=$(uname -s | tr A-Z a-z)
ARCH=$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')
curl -fsSL "https://github.com/asinha07/spoor/releases/download/v0.3.0/spoor_0.3.0_${OS}_${ARCH}.tar.gz" | tar -xz spoor
sudo mv spoor /usr/local/bin/
spoor version

    Needs Go 1.25 or newer. Installs into $(go env GOPATH)/bin.

    go install github.com/asinha07/spoor/cmd/spoor@latest

    The image speaks MCP over stdio by default. Inside Docker, localhost is the container, so use host.docker.internal for backends on your machine.

    docker run -i --rm \
  -e SPOOR_METRICS_URL=http://host.docker.internal:8428 \
  -e SPOOR_LOGS_URL=http://host.docker.internal:9428 \
  -e SPOOR_TRACES_URL=http://host.docker.internal:10428 \
  ghcr.io/asinha07/spoor:0.3.0
    git clone https://github.com/asinha07/spoor && cd spoor
make build          # ./bin/spoor
./bin/spoor version

    Download spoor_0.3.0_windows_amd64.zip (or arm64) from the releases page, unzip it and put spoor.exe on your PATH.

  2. Point it at your backends

    Pick a backend for each signal and mix them freely, then run doctor. It checks each backend from Spoor's side and says what it can and can't see.

    export SPOOR_METRICS_URL=http://victoriametrics:8428
export SPOOR_LOGS_URL=http://victorialogs:9428
export SPOOR_TRACES_URL=http://victoriatraces:10428

spoor doctor --since 15m
spoor what-changed --since 30m --pretty

    Also Mimir and Thanos for metrics. Loki and Tempo have no UI of their own, so set Grafana datasources in the config for evidence links. Tempo statistics come from a sample of traces, and the answer says so.

    export SPOOR_METRICS_TYPE=prometheus SPOOR_METRICS_URL=http://prometheus:9090
export SPOOR_LOGS_TYPE=loki SPOOR_LOGS_URL=http://loki:3100
export SPOOR_TRACES_TYPE=tempo SPOOR_TRACES_URL=http://tempo:3200

spoor doctor --since 15m

    APM transactions, logs and spans through NRQL, with a User key (NRAK-…). Spoor sends read-only queries only. New Relic samples spans with a bias towards slow and failed requests, so a span change is reported only when the service's own metrics agree.

    export SPOOR_METRICS_TYPE=newrelic
export SPOOR_LOGS_TYPE=newrelic
export SPOOR_TRACES_TYPE=newrelic
export NEW_RELIC_ACCOUNT_ID=1234567
export NEW_RELIC_API_KEY=NRAK-...

spoor doctor --since 15m

    For anything beyond URLs, put a spoor.yaml next to it and pass --config or set SPOOR_CONFIG. Keep passwords and tokens in environment variables such as SPOOR_LOGS_PASSWORD, not in the file. Setup per backend is in the backends guide, and every option in the configuration guide.

    No stack to try it on? make it-up && make demo-data in the repo starts empty backends and loads six incidents with known answers.

  3. Connect your agent

    Most clients start Spoor as a subprocess and talk to it over stdio. Use absolute paths: clients don't start servers from your shell.

    claude mcp add -s user spoor \
  -e SPOOR_METRICS_URL=http://localhost:8428 \
  -e SPOOR_LOGS_URL=http://localhost:9428 \
  -e SPOOR_TRACES_URL=http://localhost:10428 \
  -- /usr/local/bin/spoor serve

claude mcp list   # spoor should show as connected
    codex mcp add spoor \
  --env SPOOR_CONFIG=$HOME/spoor.yaml \
  -- /usr/local/bin/spoor serve

    Or in ~/.codex/config.toml. A full scan of a busy system can take half a minute, so raise the tool timeout:

    [mcp_servers.spoor]
command = "/usr/local/bin/spoor"
args = ["serve"]
tool_timeout_sec = 120

[mcp_servers.spoor.env]
SPOOR_METRICS_URL = "http://localhost:8428"
SPOOR_LOGS_URL = "http://localhost:9428"
SPOOR_TRACES_URL = "http://localhost:10428"

    Run one Spoor for the whole team over streamable HTTP, with a bearer token, /healthz and Prometheus /metrics. Ready-made manifests for Kubernetes, Docker Compose and systemd are in deploy/.

    export SPOOR_HTTP_TOKEN=$(openssl rand -hex 32)
spoor serve --http :8080          # MCP endpoint: http://<host>:8080/mcp

# each teammate:
claude mcp add --transport http spoor http://<host>:8080/mcp \
  --header "Authorization: Bearer $SPOOR_HTTP_TOKEN"

    Then ask: "Checkout errors went up in the last 30 minutes. What changed, and where did it start?"

    Spoor is also listed in the MCP registry as io.github.asinha07/spoor and on Glama.

Four tools. Start with the first.

Every tool takes service, since, until, baseline (previous, 1d or 7d) and budget_tokens, which caps the answer at 200 to 4,000 tokens. All are read-only. The CLI has the same four as commands.

what_changed

Ranked changes across metrics, logs and traces, with cause and echo attribution, for one service or all of them.

new_errors

Error logs that are new or spiking, with counts, first-seen time and one redacted example line.

trace_diff

Span names that got slower or started failing, with each span's share of the added latency and an example trace ID.

list_services

Services seen in the window and which signals have data for each.

Keep your raw query tools connected too. Spoor tells the agent where to look; the raw tools let it look closer. That combination is what the benchmark measures.

Spoor (n.): the track left by an animal. Spoor follows the trail a failure leaves in your telemetry back to where it started.
